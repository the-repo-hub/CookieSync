CookieSync 1.2.2 — установка релизной версии
==========================================

Chrome
------
Для обычной установки получите у администратора ссылку на расширение
в Chrome Web Store и нажмите «Установить». ZIP предназначен для загрузки
издателем в магазин; сам по себе он не является установщиком для пользователя.
В корпоративной среде установку также может настроить администратор браузера.

Firefox 140 или новее
--------------------
Получите подписанный Mozilla файл .xpi или ссылку на страницу дополнения в AMO.
Для файла откройте about:addons → шестерёнка → «Установить дополнение из файла».
Архив firefox-unsigned.zip ещё не подписан и для постоянной установки не подходит.
При установке Firefox сообщает о передаче данных авторизации: это cookies,
которые расширение синхронизирует с выбранным сервером.

Настройка
---------
1. Откройте CookieSync на панели расширений в нужном окне. Настройки выбираются
   автоматически по активной вкладке.
2. Укажите имя аккаунта, одинаковое для всех клиентов вашей группы.
3. По умолчанию указан ws://mnas:52314. Компьютер должен видеть сервер mnas
   в локальной сети/VPN. Администратор может сообщить другой адрес, включая wss://.
4. Домены cookies по умолчанию: .reso.ru.
5. Разрешите доступ к reso.ru и его поддоменам, затем включите синхронизацию.

При включении передаются значения ASP.NET_SessionId и ResoOffice60 с их
атрибутами и именем аккаунта. Сервер сохраняет их и передаёт другим клиентам
с тем же именем аккаунта. Выключение останавливает синхронизацию.

Для отправки должна быть открыта вкладка office.reso.ru с выполненным входом.
Если аккаунт на сервере пуст, расширение отправит уже существующие cookies.
Если cookies на сервере есть, при подключении применяется серверная пара.

Скрипт подключается по шаблону *://*.reso.ru/* (reso.ru и его поддомены),
но проверка входа выполняется именно на office.reso.ru. Текущая сборка запрашивает
доступ к сайтам для настраиваемых доменов cookies и адреса сервера.

Если расширение уже было настроено, сохранённый адрес имеет приоритет над
значением по умолчанию. Выключите синхронизацию и измените адрес вручную.

При проблеме подключения передайте администратору текст ошибки из расширения.
ws:// соответствует серверу без TLS, wss:// — серверу с доверенным сертификатом.

Приватные окна / инкогнито
-------------------------
Разрешите расширению работу в инкогнито в Chrome/Edge или в приватных окнах
в Firefox. С версии 1.1.0 каждый cookie store имеет отдельные настройки,
аккаунт и соединение. Задайте account_A в обычном окне, account_B — в приватном.
Включите каждый контекст отдельно. Контейнеры Firefox тоже настраиваются отдельно.
Для независимых сессий имена аккаунтов должны различаться.

Приватные настройки не записываются в storage.local: они остаются в оперативной
памяти (storage.session) только до закрытия последней приватной вкладки.
При новом приватном сеансе аккаунт пуст, синхронизация выключена. Все приватные
окна одного профиля обычно разделяют один приватный контекст. На сервере
аккаунт и cookies продолжают храниться независимо от закрытия окон.

При обновлении с 1.0.4 закройте все приватные окна, чтобы браузер очистил
прежнюю общую сессию, затем установите обновление и настройте приватный аккаунт.
Проверка входа перед отправкой cookies выполняется во вкладке того же хранилища.

Повторная авторизация
--------------------
С версии 1.2.0 переход от видимого окна входа к успешной авторизации запускает
обновление серверной пары, даже если cookies изменились до скрытия окна.
Такое обновление обходит пяти­минутный интервал только при совпадении ожидаемой
ревизии; более новая пара другого клиента не перезаписывается старой попыткой.
Сначала обновите сервер CookieSync до поддержки команды refresh, затем
расширение и открытые вкладки office.reso.ru.

Версия 1.2.1
------------
Исправлены гонки вкладок и повторных запросов обновления. Переключатель
синхронизации ждёт подтверждения от фонового процесса. Если сохранение настроек
не удалось, он показывает фактическое подтверждённое состояние вместе с ошибкой.
Для исправлений хранения ревизий и обработки данных обновите также сервер.

Версия 1.2.2
------------
Исправлены закрытие приватного сеанса во время восстановления фонового процесса
и повторная отправка refresh после reconnect. Ошибочный сохранённый URL теперь
можно исправить через интерфейс: выключите синхронизацию, исправьте адрес,
затем включите её снова. Выключение не требует валидного адреса подключения.
Обновите также серверную часть для исправления повторной отмены файловой записи.
