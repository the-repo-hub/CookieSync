CookieSync — установка и настройка
=================================

Что получить у администратора
----------------------------
1. Адрес сервера: по умолчанию ws://mnas:52314.
   Точный адрес и протокол сообщает администратор.
2. Общее имя аккаунта для вашей группы браузеров. Сервер создаёт аккаунт
   при первом подключении, а затем использует существующий.

Chrome / Chromium / Edge (версия 121 или новее)
----------------------------------------------
Используйте архив CookieSync-<версия>-chromium.zip.

1. Распакуйте архив в постоянную папку, например C:\CookieSyncExtension.
   В этой папке должен находиться manifest.json.
2. Откройте chrome://extensions в Chrome/Chromium или edge://extensions в Edge.
3. Включите «Режим разработчика».
4. Нажмите «Загрузить распакованное расширение» и выберите папку с manifest.json.
5. Закрепите CookieSync на панели браузера через меню расширений.

Не удаляйте и не перемещайте эту папку после установки: браузер читает файлы
расширения из неё. ZIP нужно распаковать, а не перетаскивать в окно браузера.
Если установка заблокирована политиками организации, обратитесь к администратору.

Firefox (версия 121 или новее)
-----------------------------
Используйте архив CookieSync-<версия>-firefox.zip.

Эта сборка не подписана Mozilla. В обычном Firefox её можно установить временно:
1. Распакуйте архив в отдельную папку.
2. Откройте about:debugging#/runtime/this-firefox.
3. Нажмите «Загрузить временное дополнение» и выберите manifest.json.
4. При необходимости разрешите расширению доступ к сайтам в about:addons.

Временное дополнение удаляется после перезапуска Firefox. Для постоянной
установки администратор должен получить подписанный XPI через Mozilla Add-ons
(в том числе возможно распространение без публикации в каталоге).
Переименование ZIP в XPI не заменяет подпись Mozilla.

Настройка после установки
------------------------
1. Нажмите значок CookieSync в нужном окне. Настройки выбираются автоматически
   по активной вкладке.
2. В поле «Аккаунт» введите имя, полученное у администратора.
   Для нового имени используйте 1–64 буквы, цифры, _ или - (до 200 байт UTF-8).
   Имена устройств Windows вроде CON, NUL, COM1 запрещены.
   На всех клиентах одной группы имя и регистр букв должны совпадать.
3. В поле «Сервер» вставьте полный адрес, включая ws:// или wss:// и порт.
   Имя mnas должно разрешаться в адрес сервера в вашей сети/VPN.
   Ранее сохранённый адрес не заменяется при обновлении: измените его вручную.
4. В поле «Домены куки» оставьте .reso.ru, если администратор не указал другое.
5. Переведите переключатель «Включить» в активное положение.
6. Дождитесь статуса «Онлайн».

Настройки относятся только к контексту активной вкладки. Чтобы их изменить, сначала
выключите синхронизацию в нём, измените поля и снова включите её. Окно расширения
можно закрыть. Обычные настройки сохраняются на диске, приватные — только
в памяти на время приватного сеанса.

Для отправки cookies на сервер должна быть открыта вкладка office.reso.ru,
в которой выполнен вход. Начиная с версии 1.0.2, после регистрации в пустом
аккаунте расширение само читает и отправляет уже существующие cookies — ждать
их изменения не нужно. Проверочный скрипт подключается и к вкладкам, открытым
до установки расширения. Разрешите дополнению доступ к office.reso.ru.

Если сервер уже хранит пару cookies, при подключении применяется серверная пара.
Для отправки требуются обе cookies: ASP.NET_SessionId и ResoOffice60.
Статус «Онлайн» подтверждает подключение; пояснение «Cookies не отправлены»
означает, что вход не подтверждён, пара cookies неполная или произошла ошибка.
Откройте/обновите office.reso.ru и проверьте вход, затем при необходимости
выключите и снова включите синхронизацию.

Если не подключается
--------------------
- Проверьте доступность сети/VPN, правильность адреса и имени аккаунта.
- ws:// используется с сервером без TLS, wss:// — с TLS.
- Начиная с версии 1.0.1 расширение явно разрешает ws://: Firefox больше
  не переводит его в wss:// через стандартную политику Manifest V3.
  Если установлена версия 1.0, загрузите новую сборку и перезапустите расширение.
- Для wss:// браузер должен доверять сертификату сервера; имя в адресе должно
  соответствовать сертификату. Ошибку сертификата должен устранить администратор.
- Передайте администратору текст ошибки из окна расширения.

Обновление Chrome / Edge
-----------------------
Выключите синхронизацию, замените файлы в той же папке файлами новой сборки,
на странице расширений нажмите «Обновить»/значок перезагрузки у CookieSync.
Проверьте настройки, включите синхронизацию и обновите вкладку office.reso.ru.

Обновление временной установки Firefox
-------------------------------------
Распакуйте новую Firefox-сборку в ту же папку. В about:debugging#/runtime/this-firefox
нажмите «Перезагрузить» у CookieSync. Если дополнение не установлено, загрузите
manifest.json через «Загрузить временное дополнение».
Проверьте версию 1.2.2 или новее в about:addons. Выключите синхронизацию,
укажите нужный адрес с ws:// или wss:// и включите её снова.

Приватное окно / инкогнито (с версии 1.1.0)
-----------------------------------------
Chrome/Edge: откройте страницу расширений → CookieSync → «Подробнее» →
«Разрешить использование в режиме инкогнито» / «Разрешить в InPrivate».
Firefox: about:addons → CookieSync → «Запуск в приватных окнах» → «Разрешить».

В обычном окне задайте account_A, в приватном — account_B и включите
синхронизацию для каждого отдельно. Настройки, соединения и cookies изолированы.
Приватный контекст не наследует обычный аккаунт и по умолчанию выключен.
При одинаковом имени аккаунта на одном сервере контексты намеренно попадут
в одну группу синхронизации: для независимых сессий используйте разные имена.

После закрытия всех приватных окон их настройки удаляются из памяти,
соединение закрывается. При следующем открытии выберите приватный аккаунт заново.
Перезапуск фонового worker при ещё открытых приватных окнах сохраняет настройки
в оперативной памяти через storage.session; они не записываются на диск.
Аккаунт на сервере не удаляется.

Несколько приватных окон одного профиля обычно используют общее приватное
хранилище. Для дополнительных аккаунтов используйте профили или контейнеры
Firefox. Каждый контейнер настраивается отдельно из своей активной вкладки.

При переходе с версии 1.0.4 сначала закройте все приватные окна, чтобы очистить
cookies, ранее скопированные из общего аккаунта. Затем обновите расширение,
настройте приватный аккаунт и обновите office.reso.ru в соответствующем окне.

Повторный вход при неработающих серверных cookies (с версии 1.2.0)
----------------------------------------------------------------
Если окно входа РЕСО Офис отображается, войдите обычным способом. Расширение
заметит его исчезновение и отправит актуальную полную пару cookies командой
refresh. Новая пара может заменить старую без ожидания пяти минут, если за это
время другой клиент ещё не обновил серверную ревизию. При конфликте используется
более новая серверная пара; старая попытка не перезаписывает её принудительно.

Для этой функции администратор должен сначала обновить сервер CookieSync.
После установки обновления перезагрузите вкладки office.reso.ru. Если указана
ошибка неизвестной команды refresh, передайте её администратору.

В версии 1.2.1 переключатель ожидает подтверждения сохранения. При ошибке
расширение показывает фактическое состояние: если выключить синхронизацию
не удалось, переключатель вернётся во включённое положение и появится ошибка.

С версии 1.2.2 выключатель доступен и при ошибочных сохранённых настройках.
Если URL не проходит проверку, выключите синхронизацию, исправьте адрес
и снова включите её. Операция выключения меняет только переключатель.
